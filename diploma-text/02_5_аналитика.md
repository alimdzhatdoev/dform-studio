## 2.5. Реализация модуля аналитики

Модуль аналитики представляет собой информационный дашборд в составе административной панели, обеспечивающий руководство компании актуальными данными о динамике поступления заявок, распределении заказов по услугам и статусам, а также об общих показателях деятельности. В соответствии с требованиями, изложенными в разделе 1.3, модуль должен предоставлять агрегированные данные в наглядном визуальном формате, не требовать ручного обновления и немедленно отражать изменения в базе заказов. Данный раздел описывает архитектуру модуля аналитики, серверную логику агрегирования данных, клиентскую визуализацию показателей и технические решения, применённые при реализации графиков.
Модуль аналитики активируется при выборе раздела «Аналитика» в боковой навигации административной панели и реализован в компоненте AnalyticsTab. При монтировании компонента выполняется запрос к API-эндпоинту GET /api/analytics, который возвращает агрегированный объект с аналитическими данными. Серверная обработка этого запроса считывает массив всех заказов из файла orders.json и вычисляет несколько групп показателей. Общее количество заказов определяется длиной массива. Распределение по статусам вычисляется путём итерации по массиву и подсчёта количества заявок для каждого из четырёх возможных значений статуса. Распределение по услугам вычисляется аналогичным образом: для каждого уникального идентификатора услуги подсчитывается количество связанных заявок, после чего идентификаторы заменяются названиями услуг через сопоставление с массивом из services.json.
Динамика заказов по дням вычисляется для фиксированного временного окна — тридцать дней, предшествующих текущей дате. Для каждого дня этого периода подсчитывается количество заявок, дата создания которых (поле created_at) соответствует данному дню. Результат представляет собой массив объектов с полями date и count для каждого из тридцати дней, включая дни с нулевым количеством заявок. Важно, что дни без заявок не пропускаются — они включаются в массив с нулевым значением, что обеспечивает непрерывную шкалу времени на графике и корректное визуальное восприятие периодов низкой активности. Даты преобразуются в объекты JavaScript Date для корректного сопоставления независимо от часового пояса, что является распространённым источником ошибок при работе с временными данными.
На клиентской стороне полученные данные визуализируются в нескольких блоках. Верхняя строка дашборда содержит карточки с сводными показателями: общее число заявок, число новых заявок (ожидающих обработки), число заявок в работе и число завершённых заявок. Каждая карточка содержит числовое значение, цветовую метку соответствующего статуса и текстовую метку показателя. Такое представление позволяет одним взглядом оценить текущую загрузку менеджера и общий объём работы. На рисунке 11 показан аналитический дашборд с заполненными данными.

Линейный график динамики заказов по дням реализован с использованием SVG-разметки, генерируемой непосредственно в React-компоненте без подключения сторонних библиотек визуализации. Такое решение продиктовано принципом минимизации зависимостей и достаточностью базовых возможностей SVG для построения линейного графика. Алгоритм построения графика вычисляет минимальное и максимальное значения ряда данных, масштабирует каждую точку к координатам внутри SVG-области с учётом отступов для осей, формирует строку SVG-пути (атрибут d элемента path) через команды M (moveto) и L (lineto), а также генерирует подписи осей X и Y с интерпретированными значениями. Для оси X отображается сокращённая дата через каждые семь дней, чтобы избежать перегруженности подписями при тридцатидневном периоде. Для оси Y отображается диапазон от нуля до максимального значения плюс небольшой запас. График сопровождается полупрозрачной заливкой под линией (элемент path с атрибутом fill) для лучшего визуального восприятия. Цвет линии и заливки использует акцентный цвет палитры (#E8F439), что обеспечивает визуальную согласованность с остальным интерфейсом.
При наведении курсора на область графика реализована интерактивная подсказка (tooltip): с помощью SVG-обработчиков событий onMouseMove и onMouseLeave определяется ближайшая к курсору точка данных, и рядом с ней отображается прямоугольник с датой и количеством заявок. Для этого используется вычисление позиции курсора в координатах SVG через метод getBoundingClientRect элемента, что позволяет корректно определить положение курсора независимо от масштаба страницы. Такая интерактивность превращает график из статичной иллюстрации в полноценный инструмент анализа данных.
Блок распределения заказов по статусам отображается в виде горизонтальных полосок с числовыми значениями и процентными долями. Каждый статус представлен строкой, содержащей цветной индикатор статуса, его название, числовое значение и визуальную полоску прогресса, ширина которой пропорциональна доле данного статуса в общем числе заказов. Расчёт процентной доли выполняется на клиенте на основе полученных с сервера данных о распределении по статусам. Цвета статусов соответствуют цветам, используемым в таблице заказов административной панели, что обеспечивает единообразие визуального кодирования.
Блок распределения заказов по услугам отображается в виде аналогичных горизонтальных полосок. Каждая полоска показывает название услуги, количество заявок на неё и процентную долю от общего числа. Услуги сортируются по убыванию числа заявок, что позволяет мгновенно выявить наиболее востребованные направления. Если на какую-либо услугу ещё не поступало заявок, она не включается в блок, что исключает отображение нулевых значений и концентрирует внимание на реальных данных.
Данные аналитики обновляются при каждом открытии раздела — при монтировании компонента AnalyticsTab выполняется свежий запрос к API, что гарантирует актуальность отображаемых показателей. Дополнительно в верхней части раздела реализована кнопка обновления, позволяющая перезагрузить данные без перехода к другому разделу и возврата. Это полезно при активном режиме обработки заявок, когда менеджер ожидает поступления новых обращений и периодически проверяет дашборд в реальном времени. Реализованный модуль аналитики обеспечивает руководство студии информационной основой для принятия операционных решений и завершает описание основных функциональных компонентов системы.
