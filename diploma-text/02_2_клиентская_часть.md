## 2.2. Реализация клиентской части приложения

Клиентская часть приложения представляет собой одностраничное React-приложение, реализующее весь публичный интерфейс корпоративного сайта дизайн-студии. Разработка фронтенда включала создание дизайн-системы с набором CSS-переменных, реализацию всех страниц сайта с их наполнением, организацию маршрутизации, построение системы загрузки данных с сервера и обеспечение адаптивного отображения на устройствах с различными размерами экрана. В данном разделе последовательно рассматриваются архитектура клиентского приложения, реализованная дизайн-система, структура и содержимое каждой страницы, а также принципы управления данными и состоянием в клиентском приложении.
Инициализация проекта выполнена с использованием утилиты Create React App, предоставившей готовую конфигурацию Webpack и Babel без необходимости ручной настройки системы сборки. Структура директории src организована в соответствии с принципом разделения обязанностей: страницы приложения расположены в директории pages, переиспользуемые компоненты — в components, кастомные хуки — в hooks, утилиты и вспомогательные функции — в utils, а контексты React — в context. Такая организация обеспечивает предсказуемое расположение кода и упрощает навигацию по проекту. Файл App.js является корневым компонентом, объединяющим провайдер контекста и конфигурацию маршрутизатора, а файл index.js осуществляет монтирование React-приложения в DOM-узел с идентификатором root.
Дизайн-система приложения реализована на основе CSS-переменных, определённых в корневом селекторе :root файла index.css. Переменные разделены на несколько смысловых групп. Цветовые переменные включают: --color-bg (основной тёмный фон #0C0C0E), --color-bg-alt (альтернативный фон для чередующихся секций), --color-text (основной цвет текста #F4EFE6), --color-text-muted (приглушённый текст для второстепенной информации), --color-accent (лимонно-жёлтый акцент #E8F439) и --color-border (цвет разделительных линий). Типографические переменные задают гарнитуры: --font-display для заголовков (Syne) и --font-body для основного текста (Inter). Переменные отступов определяют систему пространства: --space-xs, --space-sm, --space-md, --space-lg, --space-xl, --space-2xl — прогрессия кратных значений. Переменные для скруглений (--radius-sm, --radius-md, --radius-lg) и переходов (--transition-fast, --transition-base) дополняют систему. Использование CSS-переменных позволяет изменить визуальные характеристики всего приложения, отредактировав единственный файл, что критически важно для последовательности стиля при масштабировании.
Маршрутизация приложения настроена в файле App.js с использованием компонентов BrowserRouter, Routes и Route из библиотеки React Router 7. Публичные маршруты включают: / для главной страницы, /portfolio для раздела портфолио, /portfolio/:id для детальной страницы проекта, /services для страницы услуг, /about для страницы «О студии», /order для страницы оформления заявки и /contacts для страницы контактов. Защищённый маршрут /admin отображает компонент AdminLogin при отсутствии аутентификации и компонент Admin после успешного входа. Компоненты Header и Footer, содержащие навигацию и подвал сайта соответственно, вынесены за пределы блока Routes и отображаются на всех страницах. Исключение составляет маршрут /admin, для которого Header и Footer скрываются посредством условной проверки текущего пути, — это обеспечивает изолированный интерфейс административной панели.
Главная страница (компонент Home) реализует несколько тематических секций, последовательно знакомящих посетителя с деятельностью студии. Секция Hero является первым, что видит посетитель: она занимает полную высоту экрана и содержит крупный многострочный заголовок с акцентным цветом на выделенном слове, краткое описание студии и кнопку призыва к действию. Данные для секции Hero — тексты заголовка, описание и метка — загружаются из SiteContext, что позволяет редактировать их через административную панель без изменения кода. Секция статистики отображает ключевые числовые показатели компании в виде сетки карточек. Секция избранных проектов отображает ограниченную выборку из портфолио с кнопкой перехода в полный раздел — данные загружаются с API-эндпоинта /api/portfolio с ограничением количества результатов. Секция услуг даёт краткий обзор предлагаемых направлений с карточками, отображающими иконку, название и краткое описание каждой услуги. Финальная секция CTA содержит призыв к оформлению заявки и ссылку на форму заказа; её тексты также управляются через SiteContext.
Страница портфолио реализует отображение всех проектов с системой фильтрации по категориям. При монтировании компонента Portfolio выполняется запрос к API, возвращающий полный список проектов. Из полученных данных автоматически извлекается перечень уникальных категорий, на основе которого формируется панель фильтров. При выборе категории массив отображаемых проектов фильтруется на стороне клиента без дополнительных запросов к серверу, что обеспечивает мгновенный отклик фильтрации. Каждый проект представлен карточкой, отображающей название, категорию, год и цветовой акцент. При переходе на детальную страницу проекта (/portfolio/:id) выполняется запрос к эндпоинту /api/portfolio/:id, и отображается полная информация о кейсе: описание, теги, данные о клиенте и статистические показатели. Страница услуг (компонент Services) отображает карточки всех услуг, загружаемые с API-эндпоинта /api/services. Каждая карточка содержит иконку, название, описание, ценовой ориентир, ориентировочный срок выполнения и перечень включённых работ. Перечень работ отображается в виде структурированного списка, формируемого из массива характеристик услуги. Карточки скомпонованы в адаптивную сетку, меняющую количество колонок в зависимости от ширины экрана. На рисунке 3 представлен внешний вид страницы услуг.

Страница «О студии» (компонент About) содержит несколько блоков, данные для которых поступают из разных источников. Блок с историей студии отображает заголовок и многоабзацный текст, хранящийся в site_about и site_about_paragraphs — данные поступают через SiteContext. Блок команды отображает карточки сотрудников, загружаемые с API-эндпоинта /api/team; каждая карточка содержит цветной аватар с инициалами, имя, должность и биографию. Блок ценностей отображает карточки с иконкой, заголовком и описанием, загружаемые из настроек сайта. Блок клиентов отображает перечень компаний, с которыми сотрудничала студия. Страница контактов (компонент Contacts) реализует два функциональных блока. Первый блок отображает контактную информацию — адрес, телефон и электронную почту — с активными ссылками, позволяющими немедленно позвонить или отправить письмо при клике. Также отображаются иконки социальных сетей со ссылками на соответствующие страницы студии. Второй блок содержит краткую форму быстрой связи с полями имени, электронной почты и сообщения, которая при отправке создаёт заявку со статусом «новая» через тот же API-эндпоинт, что и основная форма заказа. Данные контактов загружаются с API-эндпоинта /api/site/contacts.
Хук useApi, реализованный в файле hooks/useApi.js, является ключевым инструментом загрузки данных в компонентах. Хук принимает функцию-загрузчик и опциональный массив зависимостей, вызывает загрузчик при монтировании компонента, управляет флагами состояния загрузки и ошибки и возвращает объект с тремя полями: data (загруженные данные), loading (булев флаг состояния загрузки) и error (объект ошибки при её наличии). Компоненты, использующие хук, отображают индикатор загрузки (скелетон или спиннер) пока loading равно true, сообщение об ошибке если error не равно null, и фактическое содержимое при наличии данных. Такой подход централизует логику управления состоянием асинхронных запросов и исключает её дублирование в каждом компоненте.
Модуль api.js в директории utils содержит именованные функции для каждого API-эндпоинта: getPortfolio, getPortfolioItem, getServices, getTeam, getSite, getOrders, createOrder, updateOrderStatus и другие. Каждая функция формирует запрос с правильным методом, URL, заголовками и телом, выполняет его через Fetch API и возвращает разобранный JSON-ответ или бросает исключение при ошибке. Базовый URL формируется из переменной окружения REACT_APP_API_URL, что обеспечивает корректную работу как в режиме разработки (запросы уходят на localhost:8000), так и в производственной среде (запросы уходят на тот же домен, что и фронтенд). Наличие единого централизованного модуля для работы с API исключает рассредоточение деталей сетевых запросов по всему коду приложения и упрощает изменение API без затрагивания компонентов.
Адаптивная вёрстка реализована посредством CSS media queries на основе трёх ключевых точек перелома: 768 пикселей (планшеты) и 480 пикселей (мобильные устройства). На мобильных устройствах сетки переключаются в одноколоночный режим, навигационное меню преобразуется в мобильное меню с кнопкой переключения, размеры шрифтов масштабируются с использованием CSS-функции clamp для плавного изменения в зависимости от ширины экрана, а отступы адаптируются к уменьшенному экрану. Функция clamp(минимум, предпочтительное значение, максимум) позволяет задать размер шрифта, линейно изменяющийся между минимальным и максимальным значениями в зависимости от ширины viewport — это обеспечивает читаемость текста без резких скачков при изменении размера окна браузера. Анимации в клиентском приложении реализованы двумя способами. CSS-переходы используются для интерактивных эффектов при наведении: плавное изменение цвета ссылок и кнопок, трансформация карточек при наведении (небольшой подъём через transform: translateY), изменение фона интерактивных элементов. Все CSS-переходы опираются на переменные --transition-fast и --transition-base, задающие единообразные временные характеристики. Scroll-анимации — появление элементов при прокрутке — реализованы через Intersection Observer API: observer отслеживает входящие в область видимости элементы и добавляет к ним CSS-класс visible, активирующий анимацию перехода из прозрачного и смещённого состояния к нормальному. Это обеспечивает постепенное «раскрытие» страницы при прокрутке, создавая ощущение динамичного и живого интерфейса, соответствующего профилю дизайн-студии.
