## 2.4. Реализация административной панели

Административная панель является закрытым разделом приложения, предназначенным для управления всеми аспектами содержимого сайта и обработки поступающих заявок. В соответствии с требованиями, сформулированными в разделе 1.3, административная панель реализует полную систему управления контентом (CMS), позволяющую владельцу студии самостоятельно обновлять любой раздел публичного сайта без привлечения разработчика. В данном разделе последовательно рассматриваются реализация аутентификации и защиты доступа, организация интерфейса административной панели, управление заказами и управление контентом каждого раздела сайта.
Доступ к административной панели обеспечивается через форму входа, отображаемую по маршруту /admin для неавторизованных пользователей. При монтировании компонента AdminLogin приложение выполняет запрос к эндпоинту GET /api/auth/check для проверки наличия действующей сессии. Если сессия активна — то есть пользователь уже входил ранее и не завершил сессию — происходит автоматическое перенаправление на административный интерфейс без необходимости повторного ввода учётных данных. Если сессия не активна, отображается форма с полями имени пользователя и пароля. При отправке формы данные передаются на эндпоинт POST /api/auth/login; в случае успешной аутентификации сервер устанавливает cookie с идентификатором сессии, и компонент переходит к отображению административного интерфейса. При неверных учётных данных отображается сообщение об ошибке. На рисунке 8 представлен экран входа в административную панель.

Основной интерфейс административной панели (компонент Admin) организован как набор вкладок с навигацией в боковой панели. Боковая панель содержит логотип студии, перечень разделов и кнопку выхода из системы. При клике на кнопку выхода выполняется запрос к эндпоинту POST /api/auth/logout, сервер инвалидирует сессию и удаляет cookie, после чего происходит перенаправление на страницу входа. Разделы административной панели соответствуют основным управляемым сущностям: аналитика, заказы, портфолио, услуги, команда и настройки сайта. Каждый раздел реализован как самостоятельный компонент-вкладка, активируемый при выборе соответствующего пункта в боковой навигации. Активная вкладка выделяется визуально акцентным цветом, что позволяет пользователю мгновенно ориентироваться в текущем разделе.
Раздел управления заказами реализован в компоненте OrdersTab и предоставляет табличное представление всех поступивших заявок. Таблица содержит следующие столбцы: номер заявки, имя клиента, выбранная услуга, дата создания, форматированная в удобочитаемый вид, и текущий статус с цветовым кодированием — новые заявки отмечаются жёлтым, заявки в работе — синим, завершённые — зелёным, отменённые — серым. Строки таблицы кликабельны; при клике на строку открывается модальное окно с детальной информацией о заявке. Столбец выбора строки содержит чекбокс для потенциальных групповых операций; при клике на чекбокс прекращается всплытие события, что исключает случайное открытие модального окна при управлении выделением. На рисунке 9 показан раздел управления заказами.

Модальное окно детали заказа (компонент OrderModal) отображает полную информацию о выбранной заявке. Верхняя часть модального окна содержит идентификатор заявки, дату создания и текущий статус. Блок контактной информации отображает имя клиента, активную ссылку mailto с адресом электронной почты и активную ссылку tel с номером телефона — это позволяет немедленно связаться с клиентом в один клик. Блок описания задачи отображает полный текст, введённый клиентом в форме заказа. Блок параметров заказа содержит выбранную услугу и указанный бюджет. В нижней части модального окна располагается выпадающий список для изменения статуса заявки. При выборе нового статуса выполняется запрос к эндпоинту PATCH /api/orders/:id/status, и после получения успешного ответа статус немедленно обновляется как в модальном окне, так и в строке таблицы. Это обеспечивает мгновенную обратную связь без необходимости перезагружать список заказов.
Раздел управления портфолио реализован в компоненте PortfolioTab и предоставляет инструменты для создания, редактирования и удаления проектов. Раздел состоит из двух режимов представления: списочный режим и режим редактирования. В списочном режиме отображается таблица с именами проектов, их категориями и кнопками действий — редактировать и удалить. Кнопка добавления нового проекта открывает форму создания в режиме редактирования. При нажатии на кнопку редактирования форма заполняется данными выбранного проекта. Форма редактирования проекта содержит поля для всех атрибутов: название, категория, клиент, год, описание, акцентный цвет (с предпросмотром выбранного цвета) и три статистических показателя. Поля тегов проекта реализованы как компонент TagInput, позволяющий добавлять теги нажатием Enter или запятой и удалять их кликом на тег. После сохранения новых или изменённых данных список обновляется немедленно через локальное обновление состояния.
Удаление записей во всех разделах реализовано с обязательным подтверждением: при нажатии кнопки удаления появляется диалог с вопросом о подтверждении операции. Только после подтверждения выполняется запрос к DELETE-эндпоинту, и запись удаляется из хранилища. Такой механизм предотвращает случайное удаление данных при неловком нажатии. После успешного удаления запись немедленно убирается из отображаемого списка без повторного запроса к серверу — удалённый элемент отфильтровывается из локального состояния компонента.
Раздел управления услугами реализован в компоненте ServicesTab по аналогичному принципу. Форма редактирования услуги содержит поля для иконки (текстовое поле для эмодзи), названия, описания, цены и срока выполнения. Список характеристик услуги реализован через компонент FeaturesList, позволяющий добавлять, редактировать и удалять отдельные пункты через интерактивный интерфейс. При сохранении услуги передаётся объект со всеми полями, включая массив характеристик, который сервер сохраняет как единую запись.
Раздел управления командой (компонент TeamTab) содержит форму с полями для каждого атрибута сотрудника: имя, должность, биография, инициалы и акцентный цвет аватара. Реализован предпросмотр аватара непосредственно в форме редактирования: при изменении полей инициалов или цвета аватар в правой части формы обновляется в реальном времени, что позволяет мгновенно оценить внешний вид карточки сотрудника.
Раздел настроек сайта (компонент SiteTab) является наиболее обширным и содержит девять подразделов, соответствующих управляемым секциям публичного сайта. Подраздел Hero позволяет редактировать тексты главного экрана: пять строк заголовка с возможностью настройки акцентного слова и описание. Подраздел «О студии» предоставляет редактор многоабзацного текста с возможностью добавления, редактирования, удаления и перестановки отдельных абзацев истории студии. Подраздел CTA позволяет редактировать тексты блока призыва к действию. Подраздел «Футер» содержит поля для слогана и строки копирайта. Подраздел «Клиенты» управляет списком компаний-клиентов студии. Подраздел «Статистика» позволяет редактировать числовые показатели, отображаемые на сайте. Подраздел «Ценности» управляет блоком ценностей компании с иконками и описаниями. Подраздел «Контакты» предоставляет управление контактными данными — адресом, телефоном, электронной почтой. Подраздел «Социальные сети» позволяет задать ссылки на страницы компании в социальных сетях. На рисунке 10 показан раздел настроек сайта с активным подразделом Hero.

Механизм обновления данных в разделе настроек сайта отличается от работы с портфолио и командой: поскольку каждый подраздел содержит единственный набор данных (одну запись типа singleton), вместо операций создания и удаления здесь используется только операция обновления. При загрузке подраздела текущие значения полей отображаются в форме, пользователь вносит изменения и нажимает кнопку сохранения. Данные отправляются на PUT-эндпоинт соответствующего ресурса, и после успешного ответа форма остаётся в актуальном состоянии. Изменения немедленно отражаются в публичной части сайта, поскольку данные публичных страниц загружаются с API при каждом монтировании компонента. Таким образом, весь цикл обновления содержимого — от редактирования в панели до отображения на публичном сайте — занимает несколько секунд и не требует участия разработчика.
